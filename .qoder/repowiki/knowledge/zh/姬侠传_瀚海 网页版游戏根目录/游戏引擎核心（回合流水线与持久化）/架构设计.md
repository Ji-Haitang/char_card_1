模块以 pipeline.js 为入口编排器，采用「请求阶段（无副作用）→ 提交阶段（有副作用可回滚）」两阶段设计：
- 请求阶段：_preprocessMessage → _syncEmbeddingsWithSummaryHistory / _syncL2EmbeddingsWithEventHistory（一致性补全）→ memoryRecall.recallRelevantMemories + recallL2Events（RRF 粗排 + reranker 精排 + 因果链追溯）→ promptBuilder.buildMessages。
- 提交阶段：appendUIConversation → responseParser.run → _applyParsedSideNote/_applySummaryUpdate → syncGameDataFromVariables → renderMainText/updateAllDisplays → summaryHistoryService.append / weekHistoryService.append → storageService.saveAppState → eventRunner.maybeSchedule → autoSave。
- API 层 api-service.js 封装 OpenAI/Gemini 双后端，统一 sendMessages/sendMessagesStream，支持 AbortController 中断与 SSE 分片回调。
- 存储层 storage-service.js 提供 Write-Through Cache：内存缓存 + IndexedDB 主库 jxz_db + 独立快照库 jxz_snapshot_db，IDB 不可用时降级 localStorage；idb-storage.js/idb-snapshot.js 是底层 IDB 封装。
- 配置层 game-config.js 集中 valueRanges/npcs/locationNames/actionConfigs/defaultGameData/recallConfig/summaryConfig/bgmFileManifest 等静态数据，被 pipeline/prompt-builder/storage 等消费。
- 辅助子系统按职责拆分：prompt-data-*（提示词片段）、prompt-overrides（全局覆盖）、template-engine（模板渲染）、variable-system（SIDE_NOTE 变量注入）、embedding-service/reranker/memory-recall/worldbook-engine（向量记忆与世界书）、event-runner/summary-runner/location-runner（异步任务调度）、storage-service（持久化）、game-ui/game-helpers/game-events/game-skills/item-list/skill-list/button-sfx/bgm-manager（表现层与音效）。
- 依赖方向单向：pipeline → {api-service, prompt-builder, response-parser, variable-system, storage-service, memory-recall, embedding-service, reranker, summary-history-service, event-history-service, week-history-service}；其余文件多为纯数据或 UI 工具，不反向依赖 pipeline。
