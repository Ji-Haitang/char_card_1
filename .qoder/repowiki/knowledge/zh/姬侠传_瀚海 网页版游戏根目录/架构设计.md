根目录作为单页应用（SPA）的装配层：index.html 通过 `<script>` 按依赖顺序依次加载 `module/*.js`（从 idb-storage、template-engine 等底层无依赖模块开始，经 game-config → game-state → storage-service → prompt-data-* → worldbook-engine → prompt-builder → pipeline.js，最终挂载到 window），形成自底向上的单向依赖链；其余 HTML 文件（start-screen-noST.html、turn-based-battle-new.html、blackjack.html、farm.html、alchemy.html、world_map.html）均为 IIFE 隔离的独立子游戏，通过 postMessage 与主游戏通信，由 game-helpers.js 中的 showXxxGame() 函数以 iframe 形式嵌入。

跨子模块的统一契约包括：
- 运行环境检测：`apiService.getRunEnv()` 返回 `'file'/'webview'/'web'/'electron'`，所有对外部 API 的调用均据此选择本地或代理路径；Capacitor APK 在启动时注入 `window.Android` 标识。
- 配置持久化：LLM 与 Embedding 配置分别存于 `localStorage['jxz_apiConfig']` / `jxz_embeddingConfig']`，由 ui/config-modal.js 提供统一弹窗编辑。
- 存档双轨：ST 版使用 ST 变量 + st-converter.js 转换 .jsonl；独立前端使用 storage-service.js + idb-storage.js（jxz_db）+ idb-snapshot.js（jxz_snapshot_db）两套 IndexedDB 数据库。
- 提示词数据生成：tools/generate-prompt-data.js 将 char_card_data/ 下的 txt 源编译为 prompt-data-core/npc/actions/extra.js 四个 window.PROMPT_* 全局变量，被 worldbook-engine 和 prompt-builder 消费。
- 构建产物：打包APK.ps1 调用 Capacitor 将本目录镜像到 android/ 工程，由 apk_build 子模块负责 Gradle 编译输出 APK。
