## 简介
本工具面向内容创作者，提供批量生成"NPC对话数据、角色属性、场景描述"等提示词相关数据的能力。通过统一的脚本入口与可插拔的模板引擎，支持从结构化输入快速产出标准化输出，便于后续在运行时进行检索、拼接与渲染。**最新功能**：现已支持悬赏系统的提示词数据生成，为游戏内的悬赏缉拿玩法提供完整的数据支持。

## 项目结构
与提示词数据生成相关的代码主要分布在 tools 与 module 两个目录中：
- tools/generate-prompt-data.js：命令行脚本入口，负责参数解析、流程编排与结果落盘。
- module/*：通用能力与业务模块，包括模板引擎、变量系统、提示词构建器、NPC/动作/覆盖层、世界书、响应解析、令牌统计等。

## 核心组件
- 脚本入口 generate-prompt-data.js
  - 职责：解析命令行参数、加载配置与输入数据、调度各模块完成生成、汇总统计并写入输出文件。
  - 关键行为：读取输入源（如 JSON/CSV）、按任务类型（NPC/属性/场景/悬赏）分发处理、调用模板引擎渲染、执行覆盖策略、记录令牌用量与错误日志。
- 模板引擎 template-engine.js
  - 职责：提供模板语法解析与变量替换，支持嵌套、条件与循环等常用能力。
- 变量系统 variable-system.js
  - 职责：维护上下文变量与作用域，提供变量解析、默认值与校验。
- 提示词构建器 prompt-builder.js
  - 职责：将业务对象（NPC/属性/场景/悬赏）转换为最终提示词片段或结构化数据块。
- 数据层模块
  - prompt-data-core.js：通用数据结构定义、校验与转换。
  - prompt-data-npc.js：NPC 对话与属性生成逻辑。
  - prompt-data-actions.js：行动/事件类数据生成逻辑。
  - prompt-overrides.js：覆盖规则与优先级控制。
  - bounty-service.js：**新增** 悬赏系统专用服务，处理悬赏相关的提示词数据生成。
- 辅助与集成
  - token-utils.js：令牌估算与配额管理。
  - response-parser.js：外部响应解析与容错。
  - worldbook-engine.js：世界书/知识库注入。
  - game-config.js：游戏运行期配置读取。

## 详细组件分析

### 脚本入口：generate-prompt-data.js
- 功能要点
  - 参数解析：支持指定输入文件、输出目录、任务类型、模板选择、是否启用覆盖、并发度等。
  - 数据流：读取输入 -> 校验 -> 分派到对应生成器 -> 模板渲染 -> 覆盖合并 -> 令牌统计 -> 落盘。
  - 错误处理：对缺失字段、模板渲染失败、IO 异常等进行捕获与记录，支持继续模式与失败聚合。
  - **新增功能**：支持悬赏系统任务类型的识别与处理。
- 典型流程
  - 初始化配置与变量作用域
  - 加载模板与覆盖规则
  - 遍历输入条目，按类型调用 NPC/行动/悬赏生成器
  - 汇总统计并输出结果与日志

## 性能与扩展性
- 性能要点
  - 模板渲染缓存：避免重复解析相同模板。
  - 变量作用域复用：减少创建开销。
  - 令牌估算批量化：降低频繁估算带来的额外成本。
  - I/O 批写：合并落盘操作，减少磁盘抖动。
  - **优化**：悬赏数据生成的批量处理和缓存机制。
- 扩展建议
  - 新增任务类型：在入口增加分派分支，并在数据层新增对应生成器。
  - 新增模板族：在模板引擎注册新模板目录与命名空间。
  - 新增覆盖策略：在覆盖层添加新的匹配与合并规则。
  - **扩展点**：参考悬赏服务的实现方式，可以轻松添加其他游戏系统的提示词生成支持。

## 故障排查指南
- 常见问题
  - 输入字段缺失：查看校验日志，确认必填字段与类型。
  - 模板渲染失败：检查模板语法与变量名拼写，确认作用域是否正确。
  - 覆盖冲突：调整覆盖优先级或冲突策略，定位具体覆盖项。
  - 令牌超限：启用截断或拆分策略，必要时分批生成。
  - 外部响应异常：查看解析器的容错日志，重试或降级。
  - **悬赏相关问题**：检查悬赏目标数据完整性、赏金计算逻辑、难度评估参数。
- 定位步骤
  - 开启详细日志，定位失败节点。
  - 缩小输入范围，复现最小用例。
  - 逐步禁用覆盖与外部注入，验证问题边界。
  - **悬赏调试**：单独测试悬赏数据生成，验证赏金算法和难度评估。

## 附录：输入输出规范与最佳实践

### 输入数据格式要求
- 通用字段
  - id：唯一标识
  - type：数据类型（如 npc、action、scene、bounty）
  - content：主体内容（字符串或结构化对象）
  - tags：标签数组，用于覆盖与检索
  - version：版本号，用于覆盖优先级
- **新增悬赏数据类型**
  - target：悬赏目标信息（姓名、外貌、危险等级等）
  - reward：赏金相关信息（基础赏金、加成因素等）
  - difficulty：追捕难度评估（所需战力、特殊要求等）
  - location：目标可能出现的地点信息
- 示例结构（概念示意）
  - 单个条目：{ id, type, content, tags, version }
  - 悬赏条目：{ id, type: "bounty", content: { target, reward, difficulty, location }, tags, version }
  - 批量输入：条目数组或按类型分组的对象映射

### 输出数据结构规范

  - text：生成的提示词文本或片段
  - meta：元信息（令牌数、来源模板、覆盖项等）
  - errors：错误与警告列表
- **悬赏输出增强**
  - reward_calculation：赏金计算详情
  - difficulty_assessment：难度评估结果
  - target_profile：目标档案信息
- 示例结构（概念示意）
  - 单条输出：{ id, type, text, meta, errors }
  - 悬赏输出：{ id, type: "bounty", text, meta, errors, reward_calculation, difficulty_assessment, target_profile }
  - 批量输出：输出数组或按类型分组的对象映射

### 最佳实践建议
- 输入侧
  - 保持 id 稳定，便于增量更新与覆盖追踪。
  - 合理使用 tags 与 version，提升覆盖命中率与可控性。
  - **悬赏数据**：确保目标信息的完整性和准确性，合理设置危险等级和赏金参数。
- 模板侧
  - 模板尽量短小且可组合，避免过长导致渲染缓慢。
  - 为复杂逻辑引入自定义函数，提高可读性与复用性。
  - **悬赏模板**：使用专门的模板处理悬赏数据的特殊格式和逻辑。
- 覆盖侧
  - 明确覆盖优先级，避免隐性冲突。
  - 使用版本化覆盖，便于回滚与审计。
  - **悬赏覆盖**：针对特定悬赏目标设置精确的覆盖规则。
- 运行侧
  - 合理设置并发度与批大小，平衡吞吐与内存占用。
  - 关注令牌统计，及时截断或拆分长文本。
  - **悬赏优化**：批量处理悬赏数据，利用缓存机制提升性能。
