## 简介
本技术文档围绕“姬侠传”资源管理系统的多媒体资源管理机制展开，重点覆盖音频播放、图片加载、缓存策略、BGM管理器、音效系统、模板引擎与动态内容生成、主题系统与样式管理等。目标是帮助开发者理解系统设计与实现细节，掌握资源组织方式与最佳实践，提升整体性能与可维护性。

## 架构总览
资源管理系统以“配置驱动 + 模块解耦”的方式组织，入口页面按需引入各模块，通过统一接口进行交互。BGM与音效分别管理长时背景音与短时提示音；模板引擎负责渲染动态内容；存储层提供本地缓存与快照能力；样式与主题通过CSS变量或类名切换实现。

## 详细组件分析

### BGM管理器
职责与能力
- 管理多首背景音乐，支持按场景/情绪分类切换。
- 提供统一的音量控制接口，支持静音与淡入淡出。
- 实现预加载策略，减少切换时的卡顿。
- 暴露状态查询接口，便于UI同步显示。

关键流程
- 初始化：根据配置选择默认曲目，建立音频实例池。
- 切换：停止当前曲目，预加载目标曲目，平滑过渡播放。
- 音量：更新全局音量并持久化用户偏好。
- 预加载：在空闲时机异步加载下一首候选曲目。

```mermaid
flowchart TD
Start(["进入场景"]) --> LoadCfg["读取配置<br/>获取默认BGM"]
LoadCfg --> InitPool["初始化音频实例池"]
InitPool --> PlayDefault["播放默认曲目"]
PlayDefault --> UserAction{"用户操作?"}
UserAction --> |切换曲目| StopCurrent["停止当前曲目"]
StopCurrent --> PreloadNext["预加载目标曲目"]
PreloadNext --> FadeIn["淡入播放"]
UserAction --> |调节音量| UpdateVol["更新音量并持久化"]
UserAction --> |退出场景| Cleanup["释放资源/清理实例"]
FadeIn --> Idle(["等待下一次操作"])
UpdateVol --> Idle
Cleanup --> End(["结束"])
```

### 模板引擎与动态内容生成
职责与能力
- 解析模板字符串，支持变量替换与条件渲染。
- 提供数据绑定与循环渲染能力。
- 输出安全HTML片段，避免注入风险。

处理流程
- 输入：模板字符串 + 数据对象。
- 解析：识别占位符与指令。
- 渲染：执行替换与逻辑分支。
- 输出：拼接最终HTML。

```mermaid
flowchart TD
In(["接收模板与数据"]) --> Parse["解析模板语法"]
Parse --> BindVars["变量绑定与校验"]
BindVars --> LoopCond{"存在循环/条件?"}
LoopCond --> |是| RenderLoop["执行循环/条件渲染"]
LoopCond --> |否| DirectRender["直接替换"]
RenderLoop --> Merge["合并片段"]
DirectRender --> Merge
Merge --> Output(["返回HTML片段"])
```

## 性能与优化
- 音频预加载：在空闲时机异步加载候选曲目，降低切换延迟。
- 资源去重：对重复请求的资源进行缓存，避免重复下载。
- 懒加载：按需加载图片与模板片段，减少首屏压力。
- 音量与静音：提供静音开关，避免不必要的音频解码开销。
- 主题切换：通过CSS变量与类名切换，避免重新计算布局。
- 存储优化：批量写入与索引设计，提高读写效率。

## 故障排查指南
- 音频无法播放：检查浏览器自动播放策略与用户手势要求；确认音频路径与MIME类型正确。
- 音效无响应：验证事件绑定是否正确；检查音效资源是否存在与大小限制。
- 模板渲染异常：核对模板语法与数据类型；输出中间结果定位问题。
- 主题未生效：确认类名切换逻辑与CSS变量定义；检查样式加载顺序。
- 存储失败：检查IndexedDB权限与配额；捕获并记录错误堆栈。
