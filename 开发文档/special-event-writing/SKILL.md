# 特殊剧情事件编写（special-event.js）

## 一、动笔前必读资料（按顺序）

1. **剧情大纲**：`开发文档/` 下对应 NPC 的特殊剧情大纲 md——这是情节骨架，逐回合对照，用户的最新手改优先。
2. **NPC 角色卡**：`char_card_information/030NPC<名字>.txt`——核对自称（洞庭君"本长老/我"、钱塘君"本龙"）、非语言习惯（龙尾、鼓腮帮、咬手指）、好感度分段的行为口径（正文表现不得越过当前档位，如 20 档禁止牵手摸头）。
3. **文风规范**：`tools/generate-prompt-data.js` L172-223（写作准则）+ L251-371（活侠传 writing_style）。这两段是硬性文风要求。
4. **格式规范**：`char_card_information/110格式规范_精简版_独立前端.txt` GameMode=1 分支。
5. **枚举清单**：`char_card_information/105列表.txt`——NPC名/场景名/表情名必须从枚举取，禁止自造。
6. **工程常量**：`module/game-config.js`——`mapLocation` 合法键（如'迪坎儿村''月牙泉'）、`npcNameToId` 字母映射（A=破阵子 B=洞庭君 C=钱塘君…）。
7. **既有事件链**：`module/special-event.js` 中其他链（SYN/LXF/QTJ/Jisi/Yuzhu），对齐链式写法与优先级占用。

## 二、工程规范（事件对象）

- 结构：`{ id, name, priority, conditions, effects, text }`。
- **链式推进**：引擎触发事件后自动 `currentSpecialEvent = 本事件id`；中间回合 conditions 只写 `currentSpecialEvent: { equals: '上一环id' }`；末回合 effects 必须复位六件套：
  `GameMode set 0` / `inputEnable set 1` / `currentSpecialEvent set ""` / `mapLocation set '天山派'` / `companionNPC set []` / `userLocation set 'tianshanpai'`。
- **优先级避让**：先用 PowerShell `Select-String 'priority:' module/special-event.js` 列出全部已占用值，再选连续空档（Grep 默认只返回15条，不够）。
- **好感度只走 SIDE_NOTE**：`game-events.js` 会机械解析"好感变化"并实际加减（上升=+1、大幅上升=+2，魅力判定可翻倍）。effects 里**不要**再 `npcFavorability.X add`，否则双重叠加。
- effects 操作符：`set / add / multiply / push / concat / remove`，或直接赋值。同行 NPC 用 `companionNPC: { push: '甲' }` / `{ concat: ['乙'] }`。
- `mapLocation`、`userLocation` 取值必须与 game-config.js 的合法键一致。
- 收尾验证：`node -e "const fs=require('fs');new Function(fs.readFileSync('module/special-event.js','utf8'));console.log('OK')"`。

## 三、文本格式（text 字段）

- `<SLG_MODE>` 包裹三段：`<MAIN_TEXT>`、`<SUMMARY>`、`<SIDE_NOTE>`。
- **MAIN_TEXT**：8-12 段，每段 150-250 字；每段结尾固定 `|NPC名|场景名|表情|none`。NPC名每段只能填一个（最主要描写的），无则 `none`；场景/表情从 105 列表枚举取。对话用「」，主角用"你"，名字占位用 `{{user}}`。
- **SUMMARY**：80-120 字白描，谁在哪里对谁做了什么，保留具体人名/地点/道具/动作/结果，禁"两人交谈""关系升温"式空泛概括。
- **SIDE_NOTE**：前 4 回含"随机事件"（事件类型=选项事件，唯一选项"特殊剧情: 继续"，成功率100%，奖励留空）；末回合不含随机事件直接放行。"时间"用 HH:MM；"位置变动"填场景枚举；"剧情基调"从 平淡/紧张/激昂/欢快/悲伤/暧昧 六选一，置信度通常 ≤0.70。好感度档位节奏参照既有链：20 档链多为 不变/不变/上升/上升/上升，40 档链末回可"大幅上升"。

## 四、叙事逻辑

- **职责逻辑先核对设定**：谁负责什么差事要符合角色卡/背景设定（例：放粮归外务长老破阵子管——他被罚才轮到别人）。因果链写清：起因→为何落到当事人头上→主角为何卷入。
- **每回合功能定位明确**（参照洞庭君链）：领差→进村铺垫+埋悬念→冲突爆发→断案/高潮→余韵收束点题。
- **伏笔要回收**：随口提过的小事（"甜的能静心"）后文必须有回响；情感落点（道谢、揭秘）必须锚定前文具体事件，忌没头没尾的空泛煽情。
- **主角不抢 NPC 高光**：主角的作用是"把位置还给 NPC"（如只按手腕不替她出头），高光动作留给事件主角。
- **"尽在不言中"用静默动作**：亲密/和解不写口头表白，写披外袍、收瓜子壳、多搁一勺糖这类熟稔动作。

## 五、情节节奏

- 详写对话与关键动作，略写过渡与环境；景物白描短促，宁少勿多。
- 武打/对峙处用短句（"并指，连点。四名护卫保持着扑击的姿势僵在原地"）。
- 单段成语不超过 2 个；形容词副词不连用。
- **段落与全篇收束必须以具体动作或角色台词戛然而止**。严禁：抽象名词总结氛围、借景抒情（"月亮升起来了"）、"虽然…但是…"升华、"这一天/此时此刻"式感慨、对关系氛围的整体评价。
- 每句须推进剧情、塑造人物或营造氛围之一，否则删。

## 六、活侠传文风要点

- **对话优先**：角色说的话必须用「」直接引出作段落主体；严禁"她命令你……""她提醒你……"式转述概括。
- **尺度/格调失衡**：宏大叙事接极度日常的解构（庄重差事→"挑粮护卫记账都是你的了"）；古风语境允许现代口语化词汇破闷。
- **群像喧哗**：3 人以上插话打岔、破折号中断、少旁白缓冲（弟子嚼舌根、孩子围攻"小姐姐"）。
- **笨拙的真诚**：深情用极简动作或大白话（一碗刮净的甜豆花、"不能死喔"）；突然的真诚急坠：戏谑之后毫无过渡扔一句真心话。
- **内心剧场**：可借旁白揭露角色表里反差的小算盘，但心理描写必须提供新信息，禁止复述刚发生的动作。
- **宣判式简洁**：重大节点用系统提示般短句，字数越少力量越大。

### 负面清单（写完全文扫描一遍）

- 禁"不是X，是Y / 不是X，而是Y / 不只是X，而是Y"等对比式转折重构——直接说 Y，或用行动呈现。
- 禁用喻体：投入湖面的石子、巨浪、涟漪、惊雷、重锤、针刺、羽毛、炸弹、潮水、火山；禁动物比喻（像一只小兽/猫/狐狸）。
- 禁程式情绪句式："眼底闪过XX""嘴角勾起弧度""带着某种XX意味""近乎XX""瞳孔一缩""眼睛里亮晶晶的""声音平静没有情绪"。
- 禁用词：不容拒绝 / 难以察觉 / 不可置信 / 若有似无 / 意味深长。
- 禁古风鸡汤（"心若向阳"式）与格式化言情抒情（"眼泪如断线珍珠"式）；悲剧用白描短句。
- 禁反复贴外貌标签：首次登场点明即可。

可用 Grep 扫违禁项：
```
Grep: 不是.{1,6}(是|而是)|不只是|眼底闪过|嘴角勾|难以察觉|不可置信|若有似无|意味深长|瞳孔一缩|不容拒绝|决了堤|像一(只|个)小(兽|猫|狐狸)
```
注意区分既有事件的旧文本，只清理本次新增段落。

## 七、工作流程与常见坑

1. 读齐资料 → 核实枚举/映射/优先级 → 写 → node 语法检查 → 违禁句式扫描 → 交付时简述改动点。
2. **时间线一致性**：改完通读段落顺序，确认时辰/场景先后合理（教训：新增"晚饭"段曾插在"日头偏西"之前，需重排）。
3. **用户手改必须保留**：编辑前先 Read 最新文件状态；attached_files 提示的改动在后续替换中逐字保留；只改用户点名的部分（如只说 MAIN_TEXT 就不动 SUMMARY/SIDE_NOTE/effects）。
4. **视角统一**：全篇第二人称"你"，不要冒出"对主角"这类第三人称表述。
5. **好感度与档位对齐**：正文亲密度不得越过角色卡当前好感档位的"应允/中立/禁止"清单。
