# GAL 台本格式 · runTurn 提示词改动方案（ny / 夏瑾）

> 状态：方案稿，未改动任何文件
> 范围：runTurn 正文请求（ny 6 条消息 / 夏瑾 4 条消息）的提示词；后台请求（总结、事件、地点、支线判定等）不动

## 0. 目标与已确认的规则

| 项 | 规则 |
|---|---|
| 行类型 | `<MAIN_TEXT>` 由**叙述行**和**台词行**组成，每行一帧，每行末尾都带段尾标记 |
| 叙述行 | `叙述文本\|场景\|HH:MM\|NPC:表情;NPC:表情\|NSFW`，每行 50-120 字，不含「」 |
| 台词行 | `「说话人(表情):台词内容」\|场景\|HH:MM\|NPC:表情\|NSFW`，台词内容每行 10-80 字 |
| 承接语 | 禁止"××说/道/问""顿了顿继续说""××心想"这类引出或转述台词的写法 |
| 说话人 | 主角写玩家名（`{{user}}`），路人可以说话，说话人不受 `<NpcList>` 限制 |
| 段尾标记 | 和现在一样：`场景\|HH:MM\|NPC:表情;NPC:表情\|NSFW` |
| 正文总字数 | 1500-2000 字 |
| 台词占比 | 台词内容字数之和 > 正文总字数的 50% |
| 内心独白 | 不新增规定，自由发挥（"××心想"这类承接语仍然禁止） |

**字数统计口径**（写进提示词，避免模型理解有分歧）：正文总字数 = 叙述行全文 + 台词行中的"台词内容"。说话人、表情、「」和段尾标记都不计入。

**为什么不用改解析器**：台词行内部没有半角 `|`，按 `|` 切分后恰好 5 段，第 3 段是 `HH:MM`。因此 [GalParser](<../module/game-ui.js#L137-L220>) 会把它当作新格式标记行正常识别，`parts[0]` 就是 `「说话人(表情):台词内容」`。`split('|')[0]` 剥段尾的旧路径（[game-ui.js:1112、:1205](<../module/game-ui.js#L1205>)）也不受影响。唯一的硬约束是：**台词内容里不能出现半角 `|`**。这一点要写进提示词。

**篇幅推算**（只供参考，不写成硬规则）：台词 ≥ 750-1000 字，按每行平均约 40 字算，大约 20-25 行；叙述 ≤ 750-1000 字，按每行平均约 85 字算，大约 8-12 行。合计 **约 28-40 行，也就是 28-40 个 GAL 帧**。

#### 2.1.2 "说明 → 正文规则"（两个分支替换成同样的内容）

```yaml
  正文规则:
    结构: 正文由"叙述行"和"台词行"组成，像GAL游戏台本一样逐行推进；每行独占一行，每行末尾都必须带段尾标记
    叙述行:
      - 每行50-120字
      - 只写动作、神态、环境、心理活动，不得包含「」，不得包含任何角色说出口的话
      - 严禁用承接语引出或转述台词，如"XX说/道/问/答""XX笑道""XX顿了顿，继续说""XX心想""XX心中暗道"；也不得把台词改写成间接引语

    字数:
      - 正文总字数1500-2000字（统计叙述行全文 + 台词行的台词内容；说话人、表情、「」、段尾标记不计）

    段尾标记: 每行末尾用"|"分隔四个字段，每个字段代表一个标记
    标记顺序: 行正文|场景名|时间|NPC名:表情;NPC名:表情|NSFW行为
    NPC规则:
      - 本行在场且被描写的NPC，最多2人，首个为本行最主要描写对象；每个NPC写作"NPC名:表情"，多人用";"分隔；NPC名取自<NpcList>，表情取自<ExpressionList>；本行无NPC在场则该字段整体填"none"

      - 时间为该行剧情发生的时刻，24小时制HH:MM，必填，不可省略
      - 行与行之间时间不倒退（连续的行可以相同）
      - 本回合首行到末行的时间跨度不超过2小时
      - 末行时间不晚于23:00
      - 回忆/闪回行一律填写主线当前时间
    NSFW行为规则: （原文不变，"本段落"改成"本行"）
```

1. 改 `char_card_information/` 下的 txt：110、200COT、105、300夏瑾-核心指导、300夏瑾-输出模板说明。
2. 改 `tools/generate-prompt-data.js`：ORDER、NY_USER_TAIL、ASSISTANT_PREFILL（推荐拆成两个常量）、FRESH、WRITING_STYLE 注释。
3. 运行 `node tools/generate-prompt-data.js`，重新生成 `module/prompt-data-extra.js / -core.js / -npc.js / -actions.js`。
4. （可选）C1 / C2 / C3 的代码改动。
5. 跑 `node --test tests/gal/`。
6. 实测：ny、夏瑾各跑 GameMode 0 和 GameMode 1 一轮。检查以下几项：
   - 台词行格式；
   - 有没有承接语；
   - 叙述行有没有夹带「」；
   - 台词占比（C2 日志）；
   - GAL 逐帧演出和立绘。
7. 收尾：
   - 如果在"提示词管理"里自定义过 `ORDER / XJ_CORE_GUIDE / XJ_OUTPUT_NOTE / THINK_GUIDANCE / WRITING_STYLE`，需要恢复默认，否则旧的覆盖内容会挡住新文本；
   - `apk/www` 需要重新同步或重新打包。

## 5. 风险

- **旧存档和开场白**：LatestReply（上一轮正文）和 [050开场白](<../char_card_information/050开场白.txt>)都是内嵌对白，第一轮可能被带回旧写法。110 开头的"无视对话历史中的格式"可以压住，开场白可以以后再改写成台本格式。
- **帧数变多**：每轮从 8-12 帧变成约 28-40 帧，玩家点击翻页的次数增加约 3 倍。如果太碎，可以把台词行字数下限调高，或者只在 C1 显示层把同一说话人的连续台词合并成一页（这需要另外设计）。
- **占比不保证**：50% 的台词占比只能靠提示词引导，模型不会每次都达标。需要硬性保证的话，可以参考 `LLM输出格式校验与二轮纠错方案.md` 做校验和重试，不在本方案范围内。
